# Team review and usability worksheet

This is a reproducible protocol, not evidence of completed human review. The registered team must fill results from actual work.

## Technical review

Each member should inspect their module and be able to explain: source input and snapshot, RM570/RM660/RM90 arithmetic, stock coverage assumptions, backend roles, stale-input rejection, transaction/idempotency handling, synthetic draft semantics and MiroFish failure behaviour. Record reviewer, date, files reviewed, issue found, change made and test evidence. Confirm the final code and declarations match the demonstration.

## Timed usability comparison

Use consenting testers and fictional records. Do not collect sensitive personal information. Assign anonymous tester IDs. Alternate manual-first and app-first order to reduce learning effects.

Task: using 18 litres, 12 litres/day, threshold 3 days and a 60-litre purchase, compare supplier A (RM9.50, four days) with supplier B (RM11, one day), choose an option, justify it and create a complete approval record. Manual baseline can use a blank spreadsheet; application task uses a clean local synthetic database. Do not reset a shared live demo while someone is using it.

Record start/end at task presentation and correct draft completion. Track elapsed seconds, arithmetic errors, whether actor/reason/time were recorded, facilitator assistance and unassisted completion. Report every observation, sample size and exclusions. Calculate percentage time reduction only after both tasks have genuine measurements. Proposed 10-minute baseline and 30% improvement remain assumptions until replaced.

## Team-only declarations

Confirm registered roster (maximum five), workshop completion, any prior-owned work, third-party resources, employment/IP obligations and actual AI assistance review. The leader must review and sign the official forms; no signature or checkbox is inferred by the assistant.
